# XBTC built-in Solana test wallet (Android)

**Status:** DEVNET engineering preview. Not audited, not a mainnet wallet, not a production exchange. The app can create its own test-wallet public address. You do **not** need to install Phantom, Ledger, UniSat or the Solana CLI for this devnet test workflow.

## What "fixed signing" means

The wallet generates one cryptographic Ed25519 key on the phone and persists it encrypted under an Android Keystore AES-GCM key. On later sessions the **public wallet address remains the same**. The private signing seed is never embedded in source code, sent to GitHub, given to the backend, or exposed to the marketplace JavaScript. The Android-native wallet screen requires an explicit on-screen confirmation and Android screen-lock authentication before the XBTC devnet mint is signed. There is **no hard-coded signature, automatic approval, or arbitrary transaction-signing API**.

The encrypted Ed25519 seed is briefly decrypted in app-process memory to sign. This is different from a true hardware-isolated Solana signer and must not be represented as audited hardware custody. Android's normal Keystore doesn't itself natively sign Solana Ed25519 transactions on typical phones.

## On-device workflow

1. Install the APK generated by the Android CI build (after it passes), open **XBTC wallet**, choose **Open secure Solana test wallet**.
2. Choose **Create built-in Solana test wallet** and approve with your existing Android PIN/password. A secure lock screen is mandatory.
3. Use **Copy my public wallet address**. This address is public, unlike the secret signing seed.
4. Choose **Request free devnet test SOL**. Solana's public faucet may rate-limit or decline requests; when it does, copy the address and use https://faucet.solana.com/ . Devnet SOL is worthless testing currency, not withdrawable cash.
5. Check devnet SOL balance.
6. Choose **Sign & mint 10,000,000,000 XBTC (TEST)**, read the native confirmation, then authorize with the Android screen lock. The app constructs an allowlisted 5-instruction Solana SPL transaction: create 82-byte mint account, initialize it at 6 decimals with no freeze authority, create 165-byte token account owned by this wallet, initialize the token account, and mint 10 billion XBTC base units into it. Only public devnet endpoint is used.
7. Choose **Verify XBTC mint and supply on-chain**. Until the RPC verifies the mint address and exact token supply, **do not assume issuance succeeded**.

Wallet address stays fixed across normal app restarts/updates. Each transaction is fresh, needs approval, and has a different signature. The newly generated mint address is a separate Solana account from your wallet address.

## Limits and precautions

- **Never use this wallet on mainnet.** The production signing system must add reviewed recovery/backup, hardened transaction display and signing, better anti-phishing controls, biometric APIs as appropriate, hardware security review, secure deployment, contract/rent verification and financial/regulatory review.
- **No recovery or import is implemented.** Losing the phone, uninstalling/resetting the app, changing screen lock or losing Android Keystore secrets can permanently lose control of the devnet wallet and mint authority. Test tokens have no market value.
- The generated mint has **no registered token display metadata** (name, symbol, logo) yet. Token identity is its unique Solana mint address; do not confuse ticker collisions with ownership.
- One app installation allows **one mint attempt** by persisting mint address and signature before broadcast. If signing/broadcasting fails or stalls, check the recorded mint and signature in Explorer first. Do not overwrite the record, reinstall and remint without independently checking the network.
- Mint authority **remains active** after issuing 10B. That is not a permanent hard cap. Production governance must decide when/how to irreversibly revoke it.
- No cloud mining or hashrate proof, no XBTC transfers to buyers, no live PayPal billing, no art claim verification, and no exchange settlement are enabled.
- Every network call is native and strictly pinned to `https://api.devnet.solana.com`. The embedded marketplace WebView blocks all network loads and has no JavaScript bridge to sign arbitrary transactions.
- Native screen uses `FLAG_SECURE` to block casual screenshots and enforces Android device credential to unlock signing.
- The application disables Android backups to avoid restoring encrypted wallet data onto devices without the corresponding Keystore key.

## Production pathway

For mainnet, either (A) implement audited wallet restoration and hardened Android signing with a mainnet configuration and real SOL for rent/fees, or (B) integrate a supported audited embedded-wallet provider that can manage user auth/recovery and fee sponsorship. Network fees cannot simply disappear: a SOL-funded fee payer or fee-sponsor must cover them.

Use `solana/README.md` for the independent desktop operator workflow. It does **not** share keys with this on-device devnet wallet.

## Verification

The GitHub Android pipeline compiles the native Java code and produces a debug APK. A successful compile does not prove actual device wallet provisioning, Solana RPC availability, fee sponsorship, or successful on-chain issuance. Those require installation and an on-chain test against a real devnet faucet/node.
